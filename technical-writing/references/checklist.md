# 技術文書チェックリスト

推敲・レビューのときに上から順に確認する。大きな単位（目的・構成）の問題を先に直す。

## 目的と読者
- [ ] 文書の主題は 1 つに絞られているか
- [ ] 目標規定文（何を目標に何を主張するか）を 1 文で言えるか
- [ ] 想定読者とその前提知識が明確で、文書全体で一貫しているか
- [ ] 読者が知りたいこと（判断材料、手順、原因など）に答えているか
- [ ] 読者が抱きそうな疑問に先回りして答えているか（注意書き、FAQ、制約事項）

## 構成
- [ ] 冒頭だけで「何の文書か」「結論・要点」が分かるか
- [ ] 重要な情報が前、詳細が後ろにあるか
- [ ] 見出しから内容が想像できるか
- [ ] 分類が漏れなく、ダブりなく（MECE）、同じ階層の粒度が揃っているか
- [ ] 各章・節を単独で読んでも理解できるか
- [ ] 書き手の思考の変遷ではなく、論理の順に並んでいるか

## 段落
- [ ] 1 段落 1 トピックか
- [ ] 段落の先頭にトピックセンテンスがあるか
- [ ] トピックと無関係な文、反する文が混ざっていないか

## 文
- [ ] 一文が長すぎないか（目安 50 字、最大 80 字）
- [ ] 主語と述語が対応しているか（ねじれていないか）
- [ ] 必要な主語・目的語が省略されていないか
- [ ] 冗長な重複がないか（「まず最初に」「3 つの分類に分けられる」）
- [ ] 修飾語が被修飾語の近くにあり、係り方が一通りにしか読めないか
- [ ] 「〜は」が 1 文に重なっていないか
- [ ] 指示語（これ、それ、この）の指す対象が明確か
- [ ] 接続詞で文と文の関係が示されているか
- [ ] 語尾が言い切られているか（「〜であろう」「〜らしい」「〜のような」がないか）
- [ ] 数値・分量・範囲・期限が具体的か
- [ ] 文体（だ・である／です・ます）が統一されているか
- [ ] 口語（みたいな、とか、ちゃんと、すごく）がないか
- [ ] 誤字脱字、「てにをは」の誤りがないか

## 事実と意見
- [ ] 事実に根拠（測定結果、ログ、出典）が添えられているか
- [ ] 意見・推測が意見・推測として書かれているか
- [ ] 「〜と思われる」「〜と考えられる」で推測を事実のように見せていないか
- [ ] 仮定を置いた場合、その内容と採用理由が書かれているか
- [ ] 未確認事項が「未確認」「要確認」と明示されているか
- [ ] 参考文献・出典が正確に記載されているか

## 用語・表記
- [ ] 同じ概念に同じ用語を使っているか（表記揺れがないか）
- [ ] 略語・専門用語が初出で説明されているか
- [ ] 意味が複数ある略語を断りなく使っていないか
- [ ] 括弧を外しても文が成立するか
- [ ] 箇条書きの項目の粒度と語尾が揃っているか

## 図表
- [ ] 図表に番号とタイトルがあるか
- [ ] 本文から参照され、読み取るべき点が説明されているか
- [ ] 単位・凡例・注釈が付いているか

## 最終確認
- [ ] どのように悪意を持って読んでも、誤読できない文章か
- [ ] 「もっと短くできないか」を検討したか
