# Notion 編集をサブエージェントに任せる

## 入力

`/notion-report [--child]` という形式。`--child` が付いていたら、会話中で対象になっているページの子ページとして新規作成する。

## なぜサブエージェントに任せるか

Notion 編集は、`fetch` の結果（ページ全文）を何度も読み、保存時の自動変換で崩れた箇所を直す作業である。これをメインの会話で行うと、ページ全文がコンテキストに積み上がり、本題の議論が埋もれる。そこで、本文の確定まではメインで行い、書き込み以降はサブエージェントに任せる。

## 手順

### 1. 本文を確定する

Notion に書く本文（Markdown）を、technical-writing スキルで書いて確定させる。既存ページの一部修正だけで本文が数行に収まる場合は、この手順を省いてよい。

確定した本文は一時ファイルに保存する（バックグラウンドジョブなら `$CLAUDE_JOB_DIR/tmp`、それ以外は `mktemp -d` で作ったディレクトリ）。technical-writing の lint 用に保存したファイルがあれば、それをそのまま使う。

Notion への書き込みは社内への公開である。渡す前に、本文に認証情報の値や顧客の個人情報の実値が含まれていないことを確認する。

### 2. 書き込み先と操作を確定する

次の 3 点を確定させる。曖昧なものはユーザーに確認する。サブエージェントはユーザーに質問できないためである。

| 項目 | 内容 |
| --- | --- |
| 操作 | 新規ページ作成 / 子ページ作成（`--child`） / 既存ページへの追記 / 既存ページの部分修正 |
| 対象 | 新規なら親ページの URL（または teamspace）とタイトル、既存なら対象ページの URL |
| 位置 | 追記・部分修正の場合、どの見出しの下か、どの文字列を置き換えるか |

既存ページの全置換（`replace_content`）やページ削除が必要な場合は、その旨をユーザーに確認してから依頼に含める。

### 3. サブエージェントに依頼する

Agent ツール（`subagent_type: general-purpose`）で、次のテンプレートを埋めて依頼する。パスは絶対パスに展開する。

```text
Notion ページを編集してほしい。本文の文言は確定済みなので変えないこと。

- 操作: <新規ページ作成 / 子ページ作成 / 追記 / 部分修正>
- 対象: <親ページ or 対象ページの URL、新規ならタイトル>
- 位置: <追記・修正の位置。新規なら「なし」>
- 本文: <本文ファイルの絶対パス>（Read で読むこと）
- 全置換・削除: <許可する / 許可しない>

手順:
1. まず <このスキルのディレクトリ>/references/notion-editing.md を読み、その規則に従う。
2. 対象ページを fetch して構造を確認してから書き込む。
3. 書き込み後にもう一度 fetch し、自動リンク化・数式化・太字崩れなど、本文と食い違う箇所が無いか確認して直す。
4. 本文の文言は変えない。Notion 記法の都合で変えてよいのは、エスケープ・インラインコード化・コードブロックの言語指定・Mermaid の向きだけである。
5. 規則上、許可されていない全置換や削除が必要になったら、書き込まずに理由を返す。

返答には次だけを書く（ページ全文は返さない）:
- ページ URL
- 実施した操作
- Notion 記法の都合で本文から変えた箇所
- 直しきれなかった崩れ（無ければ「なし」）
```

### 4. 結果をユーザーに伝える

サブエージェントの返答から、ページ URL と、本文から変えた箇所・残った崩れをユーザーに伝える。直しきれなかった崩れがあれば、その箇所と原因を添えて対応をユーザーに相談する。

Notion 特有の新しい罠を踏んだときは、`references/notion-editing.md` の「ハマりどころ」に追記する。
