# システム構成図

## なぜサブエージェントに任せるか

座標を決めて描画し、PNG を見て直す作業は、毎回画像と JS を読み直す往復になる。これをメインの会話で行うと、画像と座標がコンテキストに積み上がり、本題の議論が埋もれる。そこで、何をどう並べるかまではメインで決め、座標決めから目視確認までをサブエージェントに任せる。

## 全体の流れ

| 工程 | 担当 |
| --- | --- |
| 1. 図で伝えることを決める | メイン |
| 2. 相対配置を決め、設計メモに書く | メイン |
| 3. 座標を決めて描画し、目視確認で直す | サブエージェント |
| 4. 最終確認してレビューに出す | メイン |
| 5. 修正依頼を反映する | メイン → 同じサブエージェント |
| 6. 貼り付け | メイン |

### 1. 図で伝えることを決める

誰に何を伝える図か、登場する構成要素と、それぞれが何を入力し何を出力するか、どこで動くかを洗い出す。曖昧ならユーザーに確認する。サブエージェントはユーザーに質問できないため、ここで曖昧さを残さない。

現状と変更後を比べる図なら、2枚を同じ配置で作る（差分が一目で分かるようにする）。

### 2. 相対配置を決め、設計メモに書く

下の「色の意味」と「配置のルール」に沿って、次の項目を決める。px 単位の座標は決めない（サブエージェントが決める）。

| 項目 | 内容 |
| --- | --- |
| 目的 | 誰に何を伝える図か（1〜2文） |
| 出力 | 枚数とファイル名（2枚組なら両方） |
| 枠 | システムの枠ごとに、見出し・補足と、左右・上下のどこに置くか |
| 箱 | 構成要素ごとに、入る枠・段（上段/中段/下段）・枠内での並び順・見出しと補足行・種類（通常/新設/問題の起点/外部/DB）・バッジ |
| 矢印 | 始点 → 終点、ラベル（1行は全角15文字程度まで）、色（通常/問題/望ましい）、破線かどうか、長い線ならどの帯を通すか |
| 凡例 | 図中で使う色・線種と、その説明 |
| 2枚組の差分 | 2枚目で増える・消える・色が変わる要素（変わらない要素は同じ位置に置く） |

図中の言葉は、設計書など読み手が知っている言葉にする（実装上の変数名を出さない）。

決めた内容を Markdown の設計メモとして一時ファイルに保存する（バックグラウンドジョブなら `$CLAUDE_JOB_DIR/tmp`、それ以外は `mktemp -d` で作ったディレクトリ）。PNG の出力先も同じディレクトリにする。

### 3. サブエージェントに依頼する

Agent ツール（`subagent_type: general-purpose`）で、次のテンプレートを埋めて依頼する。パスは絶対パスに展開する。返ってきた agent ID は、5 の修正依頼で使うので控えておく。

```text
システム構成図を作ってほしい。図の内容と相対配置は設計メモで確定済みなので、
座標を決めて描画し、目視確認で直すところまでを担当すること。

- 設計メモ: <設計メモの絶対パス>（Read で読むこと）
- 作業ディレクトリ: <絶対パス>（本体 JS と PNG はここに置く）
- スキル: ~/.claude/skills/system-diagram/SKILL.md

手順:
1. スキルの SKILL.md のうち「部品」以降（部品・色の意味・配置のルール・確認リスト・ハマりどころ）を読む。
   雛形として examples/ の JS も読む。
2. 設計メモの相対配置どおりに座標を決め、assets/lib.js の関数を呼ぶだけの本体 JS を書く。
3. python3 ~/.claude/skills/system-diagram/scripts/render.py <本体.js> <出力.png> で PNG にする。
4. PNG を Read で見て、確認リストを全部満たすまで 2〜3 を繰り返す。
5. 設計メモの内容（構成要素・矢印の向き・言葉・色の意味）は変えない。
   重なりを避けるために必要なら、枠内の並び順や線の通り道は変えてよい。
   ただし左右・上下の配置を入れ替える必要が出たら、変えずに理由を返す。

返答には次だけを書く（JS や座標は返さない）:
- PNG と本体 JS の絶対パス
- 設計メモから変えた箇所と理由（無ければ「なし」）
- 確認リストのうち満たせなかった項目と理由（無ければ「なし」）
```

### 4. 最終確認してレビューに出す

サブエージェントの返答を確認し、PNG を Read で1回だけ見る。設計メモの意図（伝えたいことが一目で分かるか、比べたいものが並んでいるか）とズレていれば、5 と同じ手順で差し戻す。

問題なければ `~/Desktop` に cp し、パスと、設計メモから変えた箇所・満たせなかった項目をユーザーに伝えてレビューを受ける。レビュー前に Notion などへ貼らない。

### 5. 修正依頼を反映する

ユーザーの修正依頼は、SendMessage で 3 と同じサブエージェントに送る。座標と本体 JS の文脈を引き継いだまま直せるためである。依頼が相対配置の変更（枠の左右入れ替え、要素の追加・削除など）に及ぶ場合は、先に設計メモを更新してから送る。返答を受けたら 4 に戻る。

### 6. 貼り付け

Notion へのアップロード（`notion-create-file-upload` → curl で送信）は権限設定で拒否されることがある。拒否されたら迂回せず、Desktop の画像をユーザーに手で貼ってもらう。

## 部品（assets/lib.js）

| 関数 | 用途 |
| --- | --- |
| `panel(x,y,w,h,見出し,補足,titlePos)` | システムの枠。`titlePos='bottom'` で見出しを枠の下端に置く |
| `box(x,y,w,h,見出し,[補足行],cls,badge)` | 構成要素の箱。cls は `''`/`'new'`/`'warn'`/`'ext'`。badge は `{t:'新設',c:'#12b76a'}` |
| `db(x,y,w,h,見出し)` | DB の円柱 |
| `arrow(d,cls)` / `arrow2(d,cls)` / `line(d,cls)` | 矢印・両方向矢印・先端なしの線。d は SVG パス。cls は `''`/`'cross'`/`'good'`、破線は `'dash'` を足す |
| `lbl(x,y,[行],cls,anchor)` | 線に添えるラベル。白い縁取り付き |
| `legendItem(x,y,kind,説明)` | 凡例。kind は `'line:good'` などの線か、箱の cls |

色や太さは `assets/theme.css`、矢印の先端は `assets/defs.svg` にある。

## 色の意味（既定）

色は飾りではなく意味を持たせる。図ごとに変えてよいが、必ず凡例を付ける。

| 見た目 | 意味 |
| --- | --- |
| 赤の線（`cross`） | 問題のある依存（例：取り決めの無い、境界をまたぐ依存） |
| 緑の線（`good`）・緑の箱（`new`） | 望ましい依存（例：契約で固定）・新設するもの |
| 青の箱（`ext`） | 外部のサービス（IdP など） |
| オレンジの箱（`warn`） | 問題の起点になっている箇所 |
| 破線（`dash`） | 未決・扱いを決めていないもの |
| 灰色 | 通常の依存 |

## 配置のルール

- **比べたいシステムは同列に並べる**：同じ大きさの枠を左右に置く。
- **上から下へ流す**：ブラウザ・外部サービスは上、アプリは中段、DB は下。
- **矢印は縦と横の線だけで描く**：斜めの線は使わない。パスは `M x,y V y2 H x2` の形で書く。
- **矢印は箱の縁で止める**：先端が箱に刺さったり手前で止まったりしないよう、終点を縁から 2px 手前にする。
- **ラベルは短く、長ければ改行する**：1行は全角15文字程度まで。
- **見出しと矢印を競合させない**：枠の上から矢印が多く入るときは、`titlePos='bottom'` で見出しを下に移す。
- **長い線は空いた帯を通す**：箱の並びの間ではなく、箱の無い帯（DB の上など）を通す。

## 確認リスト

PNG を見て、次をすべて満たすまで直す。

- [ ] ラベル同士、ラベルと箱、ラベルと見出しが重なっていない
- [ ] 線が箱や見出しの文字を貫いていない
- [ ] 矢印の向きと始点・終点が意図どおり（どこからどこへのデータの流れか）
- [ ] 凡例が図中の色・線種と一致している
- [ ] 図の中の言葉が、設計書など読み手が知っている言葉と一致している（実装上の変数名を出さない）
- [ ] 2枚組の図なら、変わらない要素の位置が2枚で揃っている

## ハマりどころ

- `box` の badge に文字列を渡すと、そこで JS が止まり、それ以降の要素がすべて描かれない。必ず `{t, c}` のオブジェクトで渡す。図が途中で欠けていたら、まずここを疑う。
- フォントは Hiragino を前提にしている。macOS 以外では文字幅が変わるので座標を見直す。
- `render.py` は PNG と同じ場所に HTML も書き出す。座標の微調整は、その HTML をブラウザで開いて確かめると速い。
